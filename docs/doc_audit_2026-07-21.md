# Documentation Audit — 2026-07-21

**Scope:** All 37 docs in `docs/` plus `CLAUDE.md`, checked against the working copy (not git history)
at `main` @ `05e05ea` with uncommitted changes present. **No code was modified.**

**Verdict on the document-driven architecture: it holds.** The data-factory pattern, the
`EffectDispatcher` single-dispatch rule, `Resource`-subclasses-are-pure-data, and
signals-over-references are all still obeyed in the shipped code — including by the systems built
*after* the last doc pass. Nothing found in this audit was an architectural violation. What was wrong
was **bookkeeping**: the reference docs had drifted 2.5 months behind a period of unusually heavy
feature work, to the point where the primary "read this first" doc actively misdescribed the engine.

## 2. The big structural gap

**The combo-chain combat layer — the game's identity system — was absent from every top-level
reference doc.** `combat_chain_architecture.md` existed and was good, but:

- `CLAUDE.md`'s doc table did not list it;
- `engine_reference.md` (the "read this first" doc) never mentioned combos, kits, `ChainFactory`,
  `SkillFactory`, `ChoreographyRunner`, the input-condition seam, or Q/E skills;
- the doc itself was headed "Status: Design", with a §0 asserting choreography had no content.

An implementer following the documented reading order would have had no idea the system existed.

**Fixed by:** a new "Combo-Chain Combat Layer" section in `engine_reference.md` (pieces table,
press-to-hit walkthrough, input contract, cadence signals, kit coverage), promotion of
`combat_chain_architecture.md` to Tier 1 in `CLAUDE.md`, and a SHIPPED banner on that doc that keeps
its reasoning while flagging the two now-historical claims in §0.

## 5. Systems that existed in code but in no reference doc

Now documented in `engine_reference.md`: **descent & level streaming** (`BlockManager`,
`DepthTracker`, `LdtkLevelDirector`, `LdtkExitZone`, `FlowField`), the **two-layer mod system**
summary, **audio** (`AudioManager` + `SoundTable`), **run modes** (`use_descent_mode`,
`training_mode`, `use_ldtk_level_1`), and the **`SkillComponent`** 7th component on the player.

The `get_effective_phase()` rule is called out in three places, because it is the easiest thing to get
wrong: in descent mode, difficulty tracks **spatial depth**, not the wall clock. Never scale off
`phase_number`.

## 6. Doc-set hygiene

`CLAUDE.md`'s table listed 10 of 37 docs with no indication of what the other 27 were — so a reader
had no way to tell a live contract from a finished proposal. The table is now tiered:

- **Tier 2** — subsystem references (10 docs)
- **Tier 3** — level authoring (3 docs)
- **Historical / point-in-time** — explicitly enumerated, with "do NOT treat as current state"

Status banners were added to docs that read as forward-looking but had shipped:
`character_overhaul_design.md` (proposal → shipped, and now covers only 7 of 12 classes),
`fighter_kit_spec.md` (numbers superseded by `chain_factory.gd`), `block_architecture.md`

# Follow-up pass — all 7 open items resolved (same day)

Ben directed a second pass through the open list. Outcome per item:

### 1. Stale `choreography_runner.gd` header — ✅ fixed
Rewritten to state that both the player and `enemy.gd` run on it, and that changes are **not**
low-risk. Superseded in practice by item 2.

### 2. `enemy.gd` executor migration — ✅ done and verified in-engine
Ben chose "migrate now, verify in Godot". ~170 lines of duplicated executor deleted from `enemy.gd`
and replaced with the `choreo_*` host contract. Two supporting changes were required:

- **The runner gained the `"displacement_complete"` exit type**, which only enemies used (troll and
  colossus charges) — plus the optional `choreo_displacement_active()` host hook and the
  `duration + 1.5s` watchdog carried over from the old code.
- **A latent bug was fixed.** `_physics_process` returned early on active choreography *before*
  reaching its stun check, so `_end_choreography()` on stun was unreachable — a stunned boss kept
  executing its attack, contradicting both the code comment and the docs. The stun check now
  precedes the choreography block. This is a real behavior change: stuns now cut boss attacks.

Verified live in the Training Room (Godot 4.6.1, MCP-driven):

| Check | Result |
|---|---|
| `enemy.gd` compiles | ✅ (`validate_script`; it declares no `class_name`, so the false-positive gotcha doesn't apply) |
| Editor log clean for all touched files | ✅ zero entries |
| Goblin King runs choreography via the shared runner | ✅ `king_goblin_volley`, `is_channeling=true` |
| HP stance-machine branching, 100% HP | ✅ phases `0 → 1 → 2 → end` (Scepter Smash, default) |
| HP stance-machine branching, 50% HP | ✅ phases `0 → 3 → 4 → end` (Royal Rampage, enraged) |
| HP stance-machine branching, 25% HP | ✅ phases `0 → 5 → 6 → end` (Crown Nova, desperate) |
| Ancient Troll charge (`displacement_complete`, new code) | ✅ `0 → 1 (invulnerable) → 2 → end`, flags cleared, no hard-lock, normal movement resumed |
| Stun interrupts choreography (the fix) | ✅ cancelled within 30ms (`run=false ph=-1 ch=false`) and stayed cancelled while disabled |

Not yet regressed in-engine: Heart of the Deep, Warped Colossus, and a melee player kit. The shared
code paths they use are all covered by the above, but they are worth a look during normal play.

### 3. `characters.gd` "flip_h handles left/right" — ✅ resolved, comment only
**The code was already correct.** `CharacterSpriteFactory` slices all four facing rows as
`"<anim>_<facing>"` and `player._facing_variant()` picks by cursor quadrant, with an 8-way fallback
order. Only the comment was stale, and it has been corrected. No asset-fidelity problem.

### 4. `core_framework_decisions.md` reconciliation — ✅ done, and it found three more errors
The doc now carries a per-section status table. Newly found and corrected against code:

- **Enemy cap was documented as 150; it is 90** (`EnemySpawnManager.max_enemies`).
- **The instability scaling table labelled its tiers as percentages** (0-25%, 25-50%…), contradicting
  the absolute thresholds (0/31/71/121) in the same document. Now shows real thresholds.
- Confirmed accurate and marked live: phase HP/damage/spawn multipliers, instability stat and elite
  bonuses, per-rarity instability values, phase rarity weights, loot drop rates.
- Still unverified and now labelled as such: economy/hub costs/meta XP, weapon rarity stat ranges,
  and the per-minute spawn table (the spawn loop is formula-driven, not rate-driven).

### 5. `weapon-scaling-reference.md` — ✅ frozen, per design direction
Ben's call: **weapons are becoming class-locked and non-transferable, and the mod system gets a fresh
pass after the current character/ability polish phase.** So the doc was *not* extended — extending it
would be work the redesign invalidates. It and `mod_interaction_matrix.md` now carry ⛔ FROZEN
banners, and the direction is recorded in `CLAUDE.md` so nobody assumes cross-character weapon
portability in new work.

### 6. VFX system — ✅ my original finding was wrong; corrected, and a real gap filled
**Correction:** I reported the packs' `_Effect` sheets as unused. They are not. They ship as
`<node>_fx` entries in `characters.gd`, played on the **ComboFx overlay** — frame-locked to the
choreography phase and facing-aware, which is strictly better than `vfx_layers` for abilities. The
asset-utilization rule was already being honored; piloting `vfx_layers` there would have been a
downgrade of working code.

The genuine gap was elsewhere: **statuses had no visual at all** — burning, frozen and poisoned
enemies looked identical to healthy ones. Ben chose to pilot there instead. Added
`data/factories/status_vfx_factory.gd` and wired `burning` / `chilled` / `frozen` via a one-line
`_attach_aura()` helper in `StatusFactory`.

Verified live: all three overlays spawn as child `AnimatedSprite2D`s, play the `loop` animation, and
respect per-status scale (chilled reads at 0.8). Confirmed visually on three dummies with two
un-afflicted controls. `engine_reference.md` now documents which mechanism owns which visual, so the
distinction doesn't get re-muddled.

### 7. Archive folders — ✅ audited, and I had mislabelled one
`docs/obsidian/`, `docs/design_archive/`, and `docs/Archived Session Prompts - Completed/` are
genuinely archival. But **`docs/Session Prompts - Road to Release/` is the live release worklist**,
and my first pass wrongly filed it under "historical". Corrected in `CLAUDE.md`, and its
`00_EXECUTION_PLAN.md` — which had not been updated since 2026-07-06 — now carries a per-task status
table verified against source. That re-audit found:

- **Task 04 (win state) was recorded as OPEN but has shipped** (`win_screen.gd`, `credits.gd`,
  `GameManager.last_run_was_win`).
- **Task 11 (save versioning) is the only genuinely unstarted task left** — `progression_manager.gd`
  has no `SAVE_VERSION` and no `_migrate_save()`. This gets riskier every release: the 12-class
  roster, passive tree, class mods and trinkets have all changed the save shape since it was planned.
- Tasks 09, 10, 12, 16, 17, 18, 19, 20, 21, 22, 23, 26–34 all shipped since the last audit.
- 15 (audio wiring) is partial; 24 (Steam) and 25 (store copy) are blocked on Ben.
