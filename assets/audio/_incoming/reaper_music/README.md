# Biome music — 2026-08-15

Original tracks for the two silent biomes. Both are shipped (copied into
`assets/audio/music/`) and verified playing in-engine. All synthesis is REAPER
**stock only** — ReaSynth, JS tonegenerator, JS pink noise, ReaVerbate, ReaDelay,
Chorus, Saturation, ring modulator. Nothing third-party is embedded, so neither
track carries an attribution obligation.

| | `catacombs.ogg` | `nightmare_realm.ogg` |
|---|---|---|
| Loop | **96.000 s** — 24 bars @ 60 BPM | **114.000 s** — no bar grid |
| Key / centre | A Phrygian (A Bb C D E F G) | A, with an Eb tritone used sparingly |
| Pulse | **Yes** — footfall on beats 1 & 3 (every 2.0 s) | **No** — flat at every marchable interval |
| Form | A (b0–7) · B (b8–15) · A' (b16–23) | through-drifting, no sections |
| Integrated loudness | **−27.7 LUFS** | **−27.7 LUFS** |
| LRA | 3.0 LU | 9.2 LU |
| True peak | −17.4 dBFS | −14.6 dBFS |

`caves.ogg`, the mix reference, measures −27.7 LUFS / LRA 3.8 / −3.1 dBFS true peak.
Loudness is matched exactly; both tracks are deliberately denser than caves (which is
sparse ambience with isolated loud drips), which is why their true peaks sit lower at
the same perceived loudness.

## Opening the projects

`catacombs.rpp` and `nightmare_realm.rpp` open with every layer on its own named
track, in the order the composition scripts build them. Track volumes are already
the final mix. **Read this before turning knobs:**

- The projects render **two full periods** (192 s / 228 s) on purpose. The shipped
  loop is the **second** period — that is what makes the reverb tails wrap correctly.
  If you render the first period you will get a loop with its tails cut off.
- Every discrete event exists **twice**, one period apart. Move a bell and you must
  move its copy, or re-run the Python and let it do that for you.
- **Do not change a drone's frequency to a non-integer Hz.** They are 55 / 110 / 165 /
  113 / 78 / 28 Hz specifically because whole Hz over a whole-second loop lands on the
  same phase at both ends of the seam. REAPER's tonegenerator quantizes to whole Hz
  anyway, so a "fine" adjustment silently rounds and puts a click in the loop.

Levels, note choices and timings are all safe to move.

## The two calls most likely to want your ears

Everything measurable was measured, but the agent has no audio playback, so these are
the judgement calls to check first:

1. **`nightmare_realm` — the 3 Hz drone beat.** 110 Hz and 113 Hz beat against each
   other to create instability. It was 55/56 Hz first, which beat at exactly 1 Hz and
   measured as a 60 BPM pulse — wrong for the one biome that must not have one. 3 Hz
   should read as roughness. If it reads as flutter instead, drop the `abyss_detune`
   track, or move it to 112 Hz (2 Hz) / 115 Hz (5 Hz).
2. **`catacombs` — footfall prominence.** The march is the biome's signature and is
   currently well forward. If it fights the combat SFX, pull the `footfall` track down;
   `rank_shuffle` underneath it can come up to keep the sense of numbers.

## Rebuilding

```
python tools/sfx_forge/build_biome_music.py all       # render + measure + encode
python tools/sfx_forge/install_biome_music.py all     # copy into assets/audio/music/
```

`build_biome_music.py` prints clipping, periodicity, loudness and seam checks each run
and refuses to finish if the render is not actually periodic. Add `--reuse` to re-measure
and re-encode the existing render without re-rendering.

Sources: `tools/sfx_forge/music_catacombs.py`, `music_nightmare.py`, `music_lib.py`
(the loop machinery, and the reasoning behind the whole-Hz rule).

The `*_raw.wav` (two-period renders) and `*_loop.wav` (extracted loop, pre-encode)
files are gitignored working artifacts — safe to delete, regenerated by a rebuild.
